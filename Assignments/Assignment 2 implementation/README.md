# EduCloud – Assignment 2 Implementation

**Course:** Cloud Computing and Big Data Analytics (CO2)  
**Assignment:** Analyse, Evaluate and Validate a Virtualization Architecture for a Multi-Tenant University Private Cloud

## Package contents
- `scripts/analytical_model.py`: reproducible capacity-planning model.
- `scripts/platform_audit.py`: read-only check for KVM, Docker, Kata and related tools.
- `scripts/benchmark_host.py`: optional host-level timing utility (not a virtualization comparison).
- `config/model_config.json`: all model assumptions.
- `config/docker-compose.yml`: two isolated sample tenant networks.
- `evidence/benchmark_record_template.csv`: blank template for recording actual measurements.
- `results/`: outputs generated by running the included scripts.

## Run
Requires Python 3.9+ (standard library only):

```bash
python3 scripts/platform_audit.py
python3 scripts/analytical_model.py
```

Or run both with `bash run_all.sh`.

Optional Docker demonstration, with Docker Engine and Compose installed:

```bash
docker compose -f config/docker-compose.yml up -d
docker compose -f config/docker-compose.yml ps
docker compose -f config/docker-compose.yml down
```

The Compose example puts each tenant service on a separate bridge network. It is a teaching demonstration, not a complete production security boundary.

## Evidence and limitations
The analytical model calculates theoretical memory-based VM capacity and network planning capacity from the stated inputs. Its outputs are estimates, not experimental measurements. CPU overhead assumptions (KVM/QEMU 5%, Docker 2%, Kata 8%) are illustrative model inputs only. The 10% degradation value is an evaluation target, not an observed result.

The platform audit reports which tools and device files are detectable on the machine where it is executed. Tool presence alone does not prove a runtime is configured or functional.

**KVM, Docker and Kata benchmark experiments are not claimed as completed by this package.** Run them on a suitably configured Linux host and record genuine results in the evidence template. Do not report assumed or simulated values as measured results.

## Optional runtime checks
KVM/libvirt: `ls -l /dev/kvm` and `virsh list --all`  
Kata: `kata-runtime kata-check` (after installing/configuring Kata)

Commands vary by distribution and runtime version. The audit script does not install software or change host settings.
